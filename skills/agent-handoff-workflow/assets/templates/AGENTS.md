# 项目 AI 协作与接手规范

本文件记录项目约定，遵守宿主指令优先级和用户明确指令。采用模板时核实实际路径、分支、命令和权限，保留已有项目特例。

## 开发和交付

- 长期开发分支保存过程和 checkpoint；长期稳定分支只接收验收后的完整成果。新采用时建议 dev/main，已有名称沿用。
- 单人顺序任务通常在开发分支进行，日常修改不直接写稳定分支。并行/独立试验用任务分支和独立 Worktree，约定共享接口、文件与运行资源。
- 长任务期间仍需交付其他成果时，提前使用任务分支，避免未完成功能混入整批交付。
- 临时任务分支完成后，保留提交历史合入开发分支；清理前确认必要快照可从保留历史取得。
- 默认整批验收后 Squash 到稳定分支，再普通合并回开发分支；固定被验收的源提交，不重置开发历史。混有未完成工作时不能整支交付。项目采用其他集成方式时按已接受政策执行。
- main/dev 均长期保留；合入稳定分支后核实回流及验证，避免后续重复集成旧差异。

## 项目配置与权限

- 实际采用的工作流版本：适配并确认采用后填写；未核对时标“未记录/待核对”，不能只改版本号表示完成升级。
- 项目特例及接受依据：记录需要保留的目录、分支或交付差异。
- 实际开发分支／稳定分支／远程：采用时填写已核实值。
- 实际集成方式：采用时填写，包括 Squash 后回流规则。
- 本地提交政策及授权来源：根据用户已有约定填写；未确认不代表自动提交授权。
- 开发分支同步授权：记录远程、分支、任务范围及是否允许后续同范围同步。
- 稳定分支合并、推送和发布：分别核对明确授权；开发分支同步权限不包括稳定分支发布。
- 已有同范围授权持续有效；缺少提交/推送授权时继续编辑、验证和交接准备，不反复询问也不擅自扩权。

## 接手

1. 读取项目状态、当前有效 ADR 和当前工单，按明确依赖补读。
2. 核对实际分支/Worktree、提交、用户已有修改及未结束的 Git 操作；跨设备时获取相关远程历史并比较本地领先/落后情况。
3. 用代码、相关环境和测试核实完成项。文档不符时记录差异，沿符合最新用户目标的下一步继续；只暂停受缺失条件影响的动作。

核对项目规范版本和特例，Skill 更新不自动覆盖项目约定。已安装该 Skill 且有可用 Python 时，可用其中的 inspect_handoff.py 只读汇总事实；无工具时用 Git 核对，不依赖某台机器的绝对 Skill 路径。远程需显式查询，工具退出成功不代表已验收。

## 快照和恢复

- 阶段验证通过且获授权后提交，例如 `checkpoint(TASK-007): CP-01 完成图片上传`，提交正文写验证方法与结果；部分提交要验证实际拟提交内容。
- 完整快照列表从 Git 历史查询。工单只记关键里程碑、证据和接续点；旧账本只作历史索引，不再逐条同步手工账本。
- CP 编号限定任务范围，实际哈希定位代码；重复或缺失先核实，不猜测。WIP 明确未完成，不能当稳定 checkpoint。
- 推送稳定分支不能代替开发历史同步。换设备前核对开发/必要任务分支的实际同步结果及仅本机文件。
- 回退前保护当前修改、二进制和重要忽略文件；共享历史优先通过新提交恢复效果，不擅自 reset、rebase、强推或清理。

## 文档、验证和交接

- 状态文档记全局，工单记任务进度，ADR 记理由和替代关系。核心方案保存在项目正式目录；可丢弃临时产物放被忽略的 .ai/，有长期价值的产物转正并登记。
- 按风险和项目要求验证，区分通过、失败、阻塞、未执行、不适用。必要集成验证失败时停止后续交付，修复复测；一般推送授权不代表接受失败。
- 交接记录关键成果、实际分支、最近核对基线、同步状态、未提交文件、阻塞和下一步；未完成/失败也可以交接。
- 分别说明本机保存、已提交、已同步开发分支、已交付稳定分支、已推送稳定分支和已发布。
- 交付中断后核对已验收源、已有正式提交、暂存/冲突、main 回流及各远程分支状态，只完成剩余动作；不重复 Squash、不覆盖用户暂存，也不把部分推送报告成全部完成。
- 只读咨询或 Skill 审查不自动初始化项目、建工单或运行业务测试。
