# 初始化、任务定位与异常接续

## 初始化与升级

1. 确认用户指定项目和实际仓库根目录，检查是否处于父仓库或 monorepo；不要误建嵌套仓库。未使用 Git 时，仅在任务需要且授权覆盖时初始化；仍可先建立文档。
2. 读取已有规范、状态与任务索引及 AGENTS.md 记录的工作流版本。区分：缺失→创建；兼容→补齐；不同目录→记录映射；冲突→按有效约定处理。升级前备份将被替换的文件，或确认已有可恢复版本。重复执行不应覆盖历史、重复创建工单或重复追加相同规则。
3. 根据实际代码和用户目标填写模板。将已实现、规划中、观察到但未确认分开。不存在的测试命令不写成已验证命令；没有已接受决策时允许 ADR 为空。
4. 只创建当前需要的目录。检查 `.ai/` 和本地敏感资产的忽略规则；用 `git ls-files` 核实是否已有不应跟踪的文件。忽略规则不取消已有跟踪，不自动改历史或删除文件。
5. 检查实际开发/稳定分支及已接受的集成策略；新采用时可配置长期 dev/main 和 Squash 后合回 dev，已有规则不因模板升级被静默替换。更新 Skill 本身不等于迁移项目。确认本地提交、dev 同步和 main 交付各自授权，检查生成文件、链接、有效命令和相关基线；不要用整体暂存混入其他工作。

### 项目规范版本

在项目 AGENTS.md 的配置处记录实际采用的工作流版本、开发/稳定分支、集成方式和项目特例，不另外建立重复配置文件。本 Skill 当前版本为 2.2.0；版本号表示已完成的适配，不自动产生新的授权。

已有项目版本缺失时标为“未记录/待核对”，保留原规则。升级任务中先列出会改变行为的差异和需保留的特例，按用户已授权范围适配，再核对实际文档与流程，最后更新采用版本。只改 Skill 或只改版本号不算项目迁移完成；同版本也不能假定没有项目特例。关键协作策略改变时记录接受依据及相关决策。

## 定位与建立任务

- 用户指定编号或路径时优先使用它；未指定时从 PROJECT_STATUS 的活动索引定位。只有多个候选会改变实施方向时才询问。
- 新工单先检查活动与归档目录的文件名/编号，不展开全部正文。沿用项目编号；并行创建由协调者分配编号或使用项目允许的唯一后缀，创建前再次检查，碰撞时保留原件并重新分配。
- 工单至少明确：目标与非目标、可验证的验收标准、影响范围、依赖、实际开发分支及下一步。单人顺序任务通常沿用长期开发分支；并行/独立试验才增加任务分支和 Worktree。按实际复杂度补充共享接口、资源占用与集成人，不强制填写无关字段。
- 分支/Worktree 已存在时先核实归属和现场；符合任务则接续，不能重新创建或重置覆盖。
- 活动索引只保留定位信息和摘要。工单已完成且无未解决交付事项后可以归档，同时更新入链；“合并超期”不作为未定义的自动清理条件。仍被依赖的工单应保持可发现。

## 异常接续

| 观察到的情况 | 下一步 |
| --- | --- |
| 文档缺失或过期 | 用代码/Git/用户指令核对现状，记录缺口；不杜撰完成记录或审批 |
| 文档与代码冲突 | 保存差异，检查相关实现与验证；修正已证实的状态，未能核实时标待核实 |
| 工作区存在不明修改 | 保留，识别关联；只处理可明确归属的范围，必要时在独立副本继续 |
| 仓库尚无提交 | 记录无历史；不要把 `git log` 失败当成仓库损坏；初次提交仍按授权，Worktree 等操作需已有基线 |
| detached HEAD 或已有 merge/rebase | 记录当前状态；不擅自切换、中止或重写；依用户意图接续，其他不依赖操作可继续 |
| 环境缺失或历史测试失败 | 记录基线与受影响验收；执行可用验证，不把未运行写成通过 |
| 没有自动化测试 | 使用适合任务的人工/静态验证并说明覆盖；必要行为缺少验证则仍待验收 |
| 临时中断或失败现场 | 保存已完成、失败、未提交内容和恢复步骤；交接本身不要求测试全绿 |
| 交付中断后接手 | 按 Git 操作细则中的恢复表核实已完成阶段；复用已存在交付，不重复 Squash、回流或请求同范围授权 |
| 跨设备接手 | 获取并核对实际远程开发历史、本地领先/落后和所需 CP；未提交/未推送/忽略文件另行核实，不假定推 main 已同步 dev |

## 控制记录成本

- 宏观状态记能力与重要变化，工单记任务细节，ADR 记理由；相互链接，避免多处维护同一段规则。
- 证据用相对路径、符号名、用例与版本定位；长日志按需要保存，工单只留结论和定位。删除临时日志前保留必要的可复现信息。
- 简单修补保留简短变更/验证记录即可。只读咨询和 Skill 审查不触发项目初始化、建工单或业务测试。
- 新会话先读必要摘要，按明确依赖扩展；不要用“只读一个工单”阻断必要上下文。
- Git 历史保存完整 checkpoint，工单只记关键里程碑与核对时的状态。旧账本保留为历史索引，发现不一致先查实际提交和工作区，不删除旧记录或伪造补齐。
